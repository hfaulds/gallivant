# No `nil`

`nil` causes a large share of Go runtime panics. Gallivant rejects `nil` in
your code by default and pushes you towards `Option` and `Result` instead.
Existing Go code can opt out with one line in go.mod, so it still builds.

## The default

Every package of a main module is compiled with `-nonil`. In those packages:

- The predeclared identifier `nil` is an error: `use of nil in nonil module;
  use Option, Result or a zero value instead`.
- So you can't compare a value with `nil`. Use `match` or `Option` instead of
  `if p != nil`.
- `Err(nil)` is rejected.
- Files generated by cgo (`_cgo_*.go`) are exempt, since cgo's generated
  code uses `nil` freely.

- Creating the zero value of a type that has none is an error too, since
  that zero value would be nil (see [Zero values](#zero-values)).

Code you call can still hand you nil: the standard library and dependency
modules are not checked, and reflection and `unsafe` can create anything.
What `nonil` removes is producing nil in your own code.

Packages that are never compiled with `-nonil`:

- The standard library and `cmd`, and anything else in `GOROOT`.
- Dependency modules, whatever their go.mod says. Only main modules are
  checked, including every module of a workspace. The ecosystem's existing
  Go libraries keep working, and since `-nonil` only ever rejects code,
  exempting them does not weaken the check on your own code.

## Zero values

In Go every type has a zero value, and for pointers, maps, channels,
functions and interfaces it is nil. In a nonil package these types *have no
zero value*, and neither does a struct or array containing one, nor an enum
whose first variant has such a payload. Everything else keeps its zero
value: numbers, strings, bools, slices (a nil slice behaves like an empty
one), `Option[T]` (`None`), and structs and arrays made of them.

```go
type Server struct {
	Addr string
	Log  *log.Logger // Server has no zero value
}
```

A type parameter has a zero value only if every type in its constraint's
type set has one, so a type parameter constrained by `any` has none. Return
`Option[T]` where Go code would return `var zero T`.

Struct types declared outside your module (in the standard library or a
dependency) always have a zero value. Go types are designed so that their
zero value is ready to use (`strings.Builder`, `sync.Mutex`,
`bytes.Buffer`, `http.Client{Timeout: d}`), and their packages handle the
nil fields inside. Other packages of your own module follow the rules above.
Named pointer, map, channel, function and interface types from anywhere, such
as `error` and `io.Reader`, have no zero value.

For a type `T` without a zero value, these are errors:

| Code | Why | Instead |
| --- | --- | --- |
| `var x T` at package level | `x` starts as the zero value | `var x = f()`, or `Option[T]` |
| `T{}`, or `S{A: a}` leaving out a field of type `T` | omitted fields are zero | set every such field |
| `[3]T{a}`, `[]T{5: a}` | missing elements are zero | list every element |
| `new(T)` | points to a zero value | `&v`, or `new(v)` with a value `v` |
| `make([]T, n)` | n zero elements | `make([]T, 0, n)` and `append` |
| `clear(s)` on a `[]T` | sets elements to zero | `s = s[:0]` |
| `v := m[k]` with values of type `T` | zero if `k` is missing | `v, ok := m[k]`, or `option.FromOK` |
| `v := <-ch` on a `chan T` | zero once `ch` is closed | `v, ok := <-ch`, or `for v := range ch` |

Comma-ok forms still produce a zero value when `ok` is false. They are
allowed because `ok` tells you not to use it.

### Definite assignment

A local variable of a type without a zero value may be declared without a
value, but it must be assigned on every path before it is used:

```go
var w io.Writer
if path == "" {
	w = os.Stdout
} else {
	w = mustCreate(path)
}
fmt.Fprintln(w, "hello") // ok: w is assigned on both paths
```

The same applies to named results, which must be assigned before a bare
`return`. The rules:

- The analysis follows `if`, `switch`, `match`, `select`, `for`, `break`,
  `continue`, `goto`, `fallthrough`, `return` and calls to `panic`. Calls to
  functions that never return, such as `os.Exit` or `t.Fatal`, are not
  recognised: follow them with `return`.
- A `for` or `range` loop may run zero times, so an assignment inside its
  body only counts after the loop if the loop can only be left through a
  `break` that follows the assignment.
- A function literal that reads a variable must be created after the
  variable is assigned, since it may run at any time. A function literal
  that only assigns the variable is allowed, but the assignment does not
  count outside it.
- Assigning a field or element (`x.f = 1`, `x[i] = 1`) uses `x`, so `x` must
  already be assigned. Build the value with a composite literal instead.

Errors read `p is used before it is assigned (*T has no zero value in a nonil
module)`.

Known gaps: reslicing a slice beyond its length (`s[:cap(s)]`) exposes zero
elements; a named result is still zero if a deferred `recover` stops a panic
before it is assigned; and the zero values inside other modules' structs are
trusted.

## Opting out: `nonil false`

A module written before Gallivant, or one that has not been converted yet,
opts out in its go.mod:

```
module example.com/legacy

go 1.27
nonil false
```

`nonil` and `nonil true` state the default explicitly. Any other argument is
a go.mod error.

Code with no go.mod, either in GOPATH mode or built as `go run file.go`
outside a module, is also compiled with `-nonil`. It opts out on the command
line:

```
go run -gcflags=-nonil=false file.go
```

cmd/go puts its `-nonil` before any user `-gcflags`, so the user setting
wins. Put it in `GOFLAGS` (`GOFLAGS=-gcflags=all=-nonil=false`) to opt out a
whole GOPATH workspace.

## Working with the standard library

Many standard-library functions return `(T, error)` or use a nil pointer to
mean "absent". Two small standard-library packages bridge them:

```go
result.Wrap(strconv.Atoi(s))        // Result[int]: Ok(v) if err == nil, else Err(err)
result.Unwrap(r)                    // (T, error), the reverse
result.Must, result.Or, result.Map, result.Then, result.ToOption
option.FromPtr(p)                   // Some(*p) if p != nil, else None
option.FromOK(v, ok)                // from v, ok := m[k]
option.Or, option.OrZero, option.Must, option.Map, option.IsSome, option.IsNone
```

They are ordinary Go packages (`src/option`, `src/result`) and can grow
without touching the compiler.

## Status

Implemented: nonil by default for main modules and code outside modules, the
`nonil [true|false]` go.mod directive, `go list -m -json` reports
`"NoNil": true` for main modules compiled with `-nonil`, cmd/go passes
`-nonil` (and includes it in the build cache key), and the type checker
reports `use of nil in nonil module`, zero values of types without one, and
uses of unassigned variables (`types2` and `go/types`; the latter, having no
module information, trusts the zero value of every struct declared outside
the package being checked).

Future work: a `go vet` check that flags exported functions returning
nilable types where an `Option` or `Result` would be clearer; a `zeroable`
constraint so generic code can use `var zero T`; recognising functions that
never return.
