# `nonil` modules

`nil` is the source of a large share of Go runtime panics. Gallivant cannot
remove `nil` from the language without breaking every existing program and the
standard library, so it does the next best thing: a module can opt out of
writing `nil` and is pushed towards `Option` and `Result` instead.

## Opting in

```
module example.com/app

go 1.27
nonil
```

`cmd/go` passes `-nonil` to the compiler for every package in a module with the
`nonil` directive. In those packages:

- The predeclared identifier `nil` is an error: `use of nil in nonil module;
  use Option, Result or a zero value instead`.
- Comparing a value with `nil` is therefore impossible; use `match` or
  `Option` instead of `if p != nil`.
- `Err(nil)` is rejected.
- Files generated by cgo (`_cgo_*.go`) are exempt, since cgo's generated
  code uses `nil` freely.

Values of nilable types can still *be* nil: a `*T` field's zero value is nil,
and code outside the module can hand you nil. What `nonil` removes is the
habit of producing and comparing against nil in your own code. Dereferencing a
zero-value pointer still panics exactly as in Go.

## Working with the standard library

Many standard-library functions return `(T, error)` or use a nil pointer to
mean "absent". Two small standard-library packages bridge them:

```go
result.Wrap(strconv.Atoi(s))        // Result[int]: Ok(v) if err == nil, else Err(err)
result.Unwrap(r)                    // (T, error), the reverse
result.Must, result.Or, result.Map, result.Then, result.ToOption
option.FromPtr(p)                   // Some(*p) if p != nil, else None
option.FromOK(v, ok)                // from v, ok := m[k]
option.Or, option.OrZero, option.Must, option.Map, option.IsSome, option.IsNone
```

They are ordinary Go packages (`src/option`, `src/result`) and can grow
without touching the compiler.

## Status

Implemented: the `nonil` go.mod directive, `go list -m -json` reports
`"NoNil": true`, cmd/go passes `-nonil`, and the type checker reports
`use of nil in nonil module`. The directive is honoured for main modules
(including every module of a workspace); dependencies are compiled without
`-nonil`, which is harmless since the flag only ever rejects code.

A `go vet` check that flags exported functions returning nilable types where
an `Option` or `Result` would be clearer is future work.
